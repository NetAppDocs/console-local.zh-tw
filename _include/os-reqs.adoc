專用主機:: Console 代理程式不支援在與其他應用程式共享的主機上執行。主機必須是專用主機。主機可以是任何符合下列容量要求的架構：
+
--
* CPU：8 個核心或 8 個虛擬 CPU
* 記憶體：32 GB
* 磁碟空間：建議主機使用 165 GB，分割區需求如下：
+
** `/opt`：必須有 120 GiB 的可用空間
+
代理程式使用 `/opt`來安裝 `/opt/application/netapp`目錄及其內容。

** `/var`：必須有 40 GiB 的可用空間
+
Console 代理程式需要在 `/var`中使用此空間，因為 Docker 或 Podman 的架構設計是在此目錄中建立 Container。具體來說，它們會在 `/var/lib/containers/storage`目錄中建立 Container。外部掛載或符號連結無法用於此空間。

NOTE: Console 代理程式保留了 19000 到 19200 的 UID 和 GID 範圍。此範圍固定，無法修改。如果您的主機上有任何第三方軟體正在使用此範圍內的 UID 或 GID，則代理程式安裝將會失敗。NetApp 建議使用未安裝任何第三方軟體的主機，以避免衝突。

NetApp Console 本機部署使用固定位址空間進行服務間通訊。IP 位址範圍 10.42.0.0/16 和 10.43.0.0/16 用於內部網路。在部署 Console 本機部署之前，請確保這些 IP 位址範圍未指派給提供給 Console 本機部署的 VLAN 上的其他虛擬機器、DHCP 範圍、DNS 記錄或負載平衡器 VIP 集區。

有關如何變更代理程式介面的 IP 位址的說明，請參閱知識庫文章「代理程式 IP 與現有網路衝突」。

AWS EC2 執行個體類型:: 符合上述 CPU 和 RAM 需求的執行個體類型。建議使用 t3.2xlarge。


金鑰對:: 建立 Console 代理程式時，您需要選擇一個 EC2 金鑰對與執行個體搭配使用。


使用 IMDSv2 時的 PUT 回應跳數限制:: 如果 EC2 執行個體上啟用了 IMDSv2（這是新 EC2 執行個體的預設設定），則必須將執行個體上的 PUT 回應跳數限制變更為 3。如果不變更 EC2 執行個體上的限制，則在嘗試設定代理程式時會收到 UI 初始化錯誤。
+
--
* link:task-require-imdsv2.html["要求在 Amazon EC2 執行個體上使用 IMDSv2"]
* https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-IMDS-existing-instances.html#modify-PUT-response-hop-limit["AWS 文件：變更 PUT 回應跳數限制"^]


--


Azure VM 大小:: 符合上述 CPU 和 RAM 需求的執行個體類型。建議使用 Standard_D8s_v3。
